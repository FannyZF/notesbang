# 收款与资金回流策略（中国大陆个人开发者）

目标：产品面向**海外用户**，但开发者是**中国大陆个人**，需要把钱合规地收回来。

## 方案对比

| 方案 | 收款 | 资金回流 | 门槛/合规 | 适合 |
|---|---|---|---|---|
| **A. MoR + 收款账户** | FastSpring / Paddle / Lemon Squeezy 代收（代缴海外税） | 平台打款到 **Payoneer / WorldFirst / Airwallex** 美金账户 → 提现人民币到国内银行卡 | 需验证 MoR 是否接受大陆卖家；个人可行 | **推荐，改动最小** |
| **B. 境外实体 + Stripe** | Stripe Atlas 注册美国 LLC → Stripe | Stripe 打款到 **Mercury（美国行）/ Payoneer** → 回国 | ~$500 注册 + 年费 + 美国报税（Form 5472 等）；成本与维护更高 | 想长期做、要低费率与掌控 |
| **C. PayPal** | 个人账户收海外款 | 提现人民币到国内卡 | 个人可收海外款；**商户收单需企业主体**，高频易风控 | 快速验证，不适合长期 |
| **D. 转国内（支付宝/微信）** | 支付宝/微信商户 | 直接到国内账户 | 见下（重） | 仅当用户真在国内 |

## D 路线的真实门槛（转国内 = 合规大工程）
1. **主体**：官方支付宝/微信**商户收单需要 企业/个体工商户**，个人做不了。
2. **ICP 备案**：网站必须备案；**经营性**（收费）通常还需 **ICP 经营许可证**（增值电信业务）。
3. **生成式 AI 合规**：面向公众的生成式 AI 服务需 **算法备案 / 生成式AI服务备案**（网信办），并承担**内容安全审核**义务。
4. 其他：用户实名、数据境内存储、发票/税务、内容审核人力。

→ 结论：**转国内不是"改代码"能解决的，而是主体+牌照+备案的行政成本**，个人短期内不现实。

## A 路线的具体回款链路（建议）
```
海外用户 → MoR(FastSpring) 代收 → MoR 定期打款到 Payoneer 美金账户
        → Payoneer 提现/结汇 → 国内银行卡(人民币)
```
要点：
- 注册前**逐一核实** MoR 的卖家国别准入与打款方式（政策常变）。
- Payoneer / WorldFirst / Airwallex 支持大陆个人收款与结汇；留意年度结汇额度与费率。
- **税务**：中国税务居民的境外所得需依法申报（经营/劳务所得）；建议咨询会计。

## 建议
- **主路径维持海外 + A 方案（MoR + Payoneer）**：与现有产品、MoR 支付框架完全兼容，**无需改代码**。
- 若想要更低费率与更大掌控，再评估 **B（美国 LLC + Stripe）**。
- **仅当目标用户确实是国内**时，才考虑 D；届时产品还需中文化、支付宝/微信适配、备案与 AI 合规——这是战略级投入。

## 对代码的影响
- 海外路线：现有 `PAYMENT_PROVIDER` 抽象已就绪，选定 MoR 后补一个 adapter 即可。
- 国内路线：需新增支付宝/微信 provider + 中文化 UI + 备案主体信息展示 + 内容审核流程。
